# 동아리 프로필·모집관리 분리 설계

## 목표

동아리 프로필을 사용자가 목록과 상세 화면에서 보는 콘텐츠의 단일 관리 화면으로 만들고, 모집관리는 모집 기간·전형 절차·지원서 생성·게시만 담당하게 한다.

## 확정 요구사항

- 대표 커버는 동아리 목록 카드의 미리보기로 사용한다.
- 상세 화면은 동아리 프로필의 소개정보를 표시한다.
- 소개글 입력 중 상세 화면 미리보기가 실시간으로 갱신된다.
- 소개글 하단에 이미지를 최대 10장까지 첨부한다. 상세 화면에서는 한 줄 가로 스크롤로 표시한다.
- 모집상태는 운영자가 `모집중` 또는 `모집완료`로 설정한다.
- 모집중인 동아리의 상세 화면에서만 지원 버튼을 활성화한다.
- 지원 버튼은 별도 모집 상세 화면을 거치지 않고 지원폼으로 이동한다.
- 동아리 프로필에서 활동기간·활동장소를 제거한다.
- 모집 제목·모집 인원·모집 전용 소개글·추가 설명을 제거한다.
- 동아리 프로필의 소개글이 사용자에게 보이는 모집글이다.
- 모집관리는 모집 일정, 전형 설정, 지원서 생성, 게시를 관리한다.
- 운영 데이터 호환은 범위가 아니므로 신규 마이그레이션을 만들지 않는다. 초기 스키마(`V1`)와 시드(`V2`)를 새 모델에 맞게 직접 수정한다.

## 화면 구조

### 운영자 동아리 프로필

`/admin/club`은 다음을 한 화면에서 관리한다.

1. 대표 커버 업로드 및 목록 카드 미리보기
2. 짧은 소개와 상세 소개 입력
3. 상세 소개 하단 이미지 선택·삭제·순서 미리보기
4. `모집중`/`모집완료` 토글
5. 사용자 상세 화면 미리보기

새로운 이미지 파일은 저장 시 서버에 업로드하고, 기존 이미지 ID 목록은 PATCH 요청으로 원하는 순서와 삭제 상태를 저장한다. 파일 선택 직후에는 object URL로 실시간 미리보기를 표시한다.

### 운영자 모집관리

기존 wizard의 첫 단계를 `모집 일정`으로 변경한다. 첫 단계에는 지원 시작일·마감일만 둔다. 이후 단계는 전형 설정, 지원서 설계, 검토 및 게시로 유지한다. 게시 payload에는 제목·인원·콘텐츠를 포함하지 않는다.

### 사용자 동아리 화면

- 목록: 대표 커버, 동아리명, 카테고리, 짧은 소개, 모집상태
- 상세: 대표 커버, 짧은 소개, 상세 소개, 하단 이미지 가로 스크롤
- 모집중이며 게시된 모집과 지원 기간이 유효하고 아직 지원하지 않은 경우에만 `지원서 작성하기`가 `/apply/:recruitmentId`로 이동한다.
- 그 외에는 비활성 상태 문구를 표시한다.
- 활동기간·활동장소와 모집 제목·인원·별도 모집 설명은 표시하지 않는다.

## 백엔드 모델과 API

### Club

`clubs`는 `short_introduction`, `detailed_introduction`, `recruitment_status`, `cover_file_asset_id`를 보유한다. `activity_period`, `activity_place`는 생성하지 않는다.

소개 이미지는 `club_introduction_images(id, club_id, file_asset_id, display_order)`로 관리한다. 파일 자산의 목적은 `CLUB_INTRODUCTION`을 추가한다.

운영 API:

- `PATCH /api/v1/operator/clubs/{clubId}`: 소개정보, 모집상태, 기존 이미지 ID 순서 저장
- `PUT /api/v1/operator/clubs/{clubId}/cover`: 대표 커버 교체
- `POST /api/v1/operator/clubs/{clubId}/introduction-images`: 이미지 여러 장 업로드
- `GET /api/v1/clubs/{clubId}/introduction-images/{imageId}`: 공개 이미지 조회

소개 이미지는 서버에서도 이미지 형식·5MiB 제한·최대 10장 제한을 검증한다. 운영자 범위 검증은 기존 `ClubScope`를 사용한다.

### Recruitment

`recruitments`는 동아리, 지원 시작/마감일, 게시 시각, 생성자만 보유한다. 제목·인원·콘텐츠 필드는 제거한다. 전형 단계와 지원폼은 기존 구조를 유지한다.

지원 가능 여부는 다음을 모두 만족해야 한다.

- 동아리 `recruitment_status = RECRUITING`
- 게시된 모집 기간이 현재 `OPEN`
- 해당 모집의 지원폼이 존재함
- 현재 사용자가 이미 지원하지 않음

마지막 조건은 사용자 화면 표시용이며, 실제 제출 API의 기존 검증도 유지한다.

## 오류 처리

- 이미지가 10장을 초과하면 저장하지 않고 한국어 검증 오류를 표시한다.
- 잘못된 이미지 형식·크기에는 기존 파일 검증 오류 계약을 적용한다.
- 모집 상태가 완료되었거나 기간이 끝난 지원폼 접근은 서버가 `409`로 거부한다.
- 기존 모집 기간과 겹치는 게시 요청은 기존 `409` 계약을 유지한다.

## 테스트

- 백엔드: 초기 스키마 계약, 이미지 개수·형식 검증, 프로필 DTO에서 활동 필드 제거, 모집 게시 DTO에서 제목·인원·콘텐츠 제거, 모집중 상태와 지원 가능성 통합 테스트
- 운영 웹: 프로필 실시간 미리보기·이미지 최대 10장·업로드 payload, 모집 wizard payload에서 제목·인원·콘텐츠 제거, 게시 검토 상태
- 사용자 웹: 상세 화면의 활동 필드 제거, 모집중일 때 지원폼 링크 활성화, 모집완료일 때 비활성화, 소개 이미지 가로 스크롤 렌더링
