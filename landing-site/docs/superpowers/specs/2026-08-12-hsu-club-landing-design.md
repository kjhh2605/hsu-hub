# HSU Club 학생용 랜딩사이트 디자인

## 1. 목적

HSU Club 랜딩사이트는 한성대학교 학생이 서비스를 처음 접했을 때 다음 두 가지를 빠르게 판단하도록 돕는다.

1. HSU Club이 어떤 문제를 해결하는가.
2. 지금 이 서비스를 사용해 모집 중인 동아리를 둘러볼 가치가 있는가.

핵심 약속은 **“동아리 지원부터 면접까지, 여러 도구로 끊겨 있던 과정을 한곳에서 연결한다”**이다. 운영진용 기능이나 내부 관리 효율은 이번 랜딩사이트의 메시지에서 제외한다.

## 2. 대상과 전환 목표

- 주 대상: 동아리를 찾고 지원하려는 한성대학교 학생
- 1차 전환: `모집 중인 동아리 보기` CTA 클릭
- 보조 전환: 기능 소개를 끝까지 확인하고 서비스 가치를 이해하는 것
- CTA 링크: 구현 시 학생용 서비스의 동아리 탐색 화면으로 연결한다. 외부 URL이 확정되지 않은 현재는 `/explore`을 사용한다.

## 3. 메시지 원칙

- 에브리타임, 인스타그램, Google Forms, Google Sheets 자체를 비판하지 않는다.
- 문제는 개별 도구의 품질이 아니라 **하나의 지원 여정이 여러 도구로 끊기는 것**으로 정의한다.
- 검증되지 않은 사용자 수, 제휴 동아리 수, 만족도, 후기, 성과 통계는 사용하지 않는다.
- HSU Club이 현재 프로토타입에서 제공하는 학생 기능만 설명한다.
- `간편 지원`은 독립 기능으로 홍보하지 않고 전체 서비스 여정의 한 단계로만 보여준다.

## 4. 페이지 서사

페이지는 `문제 공감 → 실제 방식 비교 → 하나로 연결된 여정 → 핵심 기능 증명 → 탐색 CTA` 순서로 전개한다.

### 4.1 내비게이션

- 좌측: HSU Club 워드마크와 간단한 심볼
- 중앙/우측 앵커: `기존 방식과 비교`, `주요 기능`
- 강조 CTA: `모집 중인 동아리 보기`
- 스크롤 시 상단에 고정되고, 배경은 반투명 흰색과 약한 블러를 사용한다.
- 모바일에서는 앵커를 숨기고 워드마크와 CTA만 유지한다.

### 4.2 히어로

- 눈썹 문구: `한성대 동아리 지원, 이제 한곳에서`
- 헤드라인: `동아리 지원부터 면접까지, 한곳에서 끝내세요.`
- 설명: `에타와 인스타에서 공고를 찾고, 구글폼으로 지원하고, 스프레드시트로 면접을 잡던 과정을 HSU Club 하나로 연결했어요.`
- 주 CTA: `모집 중인 동아리 보기`
- 보조 앵커: `어떻게 달라졌나요?`
- CTA 아래 짧은 여정 라벨: `모집 탐색 · 지원 · 진행 확인 · 면접 예약`

히어로 우측에는 사용자가 제공한 학교 캐릭터를 주인공으로 한 한 장면 이미지를 배치한다. 캐릭터가 에브리타임, 인스타그램, Google Forms, Google Sheets를 상징하는 카드 사이에서 난처해하고, 흩어진 흐름이 하나의 HSU Club 모바일 화면으로 모이는 장면이다.

이미지는 다음 원칙을 지킨다.

- 원본 캐릭터의 짙은 HSU 블루 선화, 둥근 실루엣, 볼의 연한 하늘색, 가슴의 HSU 표기를 유지한다.
- 캐릭터를 브랜드 마스코트처럼 임의로 재설계하지 않는다.
- 특정 서비스의 공식 로고는 그대로 복제하지 않고, 색과 텍스트 라벨을 사용한 일반화된 UI 카드로 표현한다.
- 한 장면 안에서 혼란과 통합을 동시에 전달하되, 캐릭터가 불안하거나 실패한 모습으로 보이지 않게 한다.
- 이미지 자체에 긴 문장을 넣지 않는다. 필요한 도구명은 HTML 오버레이 라벨로 제공해 반응형과 접근성을 확보한다.

### 4.3 기존 방식과 비교

- 섹션 제목: `지원할 때마다, 몇 개의 앱을 오가고 있나요?`
- 설명: `익숙한 도구는 그대로 편리하지만, 모집부터 면접까지의 흐름은 서로 이어져 있지 않았어요.`

비교 내용은 다음 네 행으로 고정한다.

| 단계 | 지금까지의 방식 | HSU Club |
| --- | --- | --- |
| 모집 확인 | 에브리타임과 인스타그램에서 동아리별 공고를 각각 탐색 | 현재 모집 중인 동아리와 일정을 한곳에서 확인 |
| 지원 | 공고마다 연결된 별도의 Google Form으로 이동 | 공고 확인 후 서비스 안에서 바로 지원 |
| 지원 이후 | 지원 내역과 전형 진행 상황을 별도로 확인 | 내가 지원한 동아리와 현재 단계를 한 화면에서 확인 |
| 면접 조율 | 별도의 Google Sheets 링크에서 가능 시간을 확인·기입 | 가능한 슬롯을 선택하고 예약 결과를 즉시 확인 |

데스크톱에서는 3열 비교 테이블로, 모바일에서는 각 단계를 하나의 카드로 변환한다. 기존 방식은 중립적인 회색, HSU Club 방식은 옅은 블루 배경과 체크 아이콘을 사용한다. 빨간색 경고나 취소선처럼 공격적인 표현은 피한다.

### 4.4 연결된 서비스 여정

- 섹션 제목: `하나의 흐름으로 이어지는 동아리 지원`
- 단계: `동아리 찾기 → 지원하기 → 진행 상태 확인 → 면접 예약`
- 네 단계는 짧은 동사형 문장과 아이콘으로 표현한다.
- 데스크톱에서는 가로 연결선, 모바일에서는 세로 타임라인으로 배치한다.
- 지원서 편의 기능은 이 단계에서 추가로 나열하지 않는다.

### 4.5 주요 기능과 서비스 미리보기

기능은 두 개의 큰 스토리 블록으로 제한한다.

#### 모집 탐색

- 제목: `모집 중인 동아리를 한눈에`
- 설명: `카테고리와 검색으로 동아리를 찾고, 활동 내용부터 모집 일정까지 한 화면에서 확인하세요.`
- 증명 화면: 학생용 모바일 프로토타입의 탐색 화면과 동아리 상세 화면
- 보조 포인트: `카테고리 탐색`, `모집 일정 확인`, `동아리 상세 정보`

#### 지원 관리

- 제목: `지원한 순간부터 면접까지 놓치지 않게`
- 설명: `내 지원이 어느 단계인지 확인하고, 결과 알림을 받은 뒤 가능한 면접 시간을 직접 선택하세요.`
- 증명 화면: 내 지원 현황 화면과 면접 시간 선택 화면
- 보조 포인트: `진행 상태 확인`, `결과 알림`, `면접 시간 선택·변경`

제품 미리보기는 실제 프로토타입의 정보 구조와 디자인을 바탕으로 만든 정적 화면을 사용한다. 기기 목업을 과도하게 사실적으로 만들지 않고, 랜딩페이지의 블루 시스템 안에서 화면 내용이 읽히는 수준으로 구성한다. 자동 재생 캐러셀은 사용하지 않는다.

### 4.6 최종 CTA

- 눈썹 문구: `이번 학기 동아리 찾기`
- 제목: `놓치고 싶지 않은 동아리를 지금 찾아보세요.`
- 설명: `모집 공고부터 면접 예약까지, HSU Club에서 이어서 진행할 수 있어요.`
- 버튼: `모집 중인 동아리 보기`
- 캐릭터는 히어로 이미지의 작은 단독 포즈로 한 번 더 사용할 수 있다.

### 4.7 푸터

- HSU Club 워드마크
- 설명: `한성대학교 학생을 위한 동아리 모집·지원 서비스`
- 링크 자리: `이용약관`, `개인정보처리방침`
- 권리 표기: `© 2026 HSU Club`

## 5. 시각 디자인

### 5.1 방향

기본 인상은 **신뢰감 있는 캠퍼스 서비스**이며, 캐릭터와 작은 장식에서 학생다운 활기를 더한다. 행정 사이트처럼 딱딱하거나, 스타트업 랜딩페이지처럼 과장된 글로우와 수치를 남발하지 않는다.

### 5.2 색상

- Ink: `#0B1F3A`
- HSU Blue: `#0C4A8A`
- Action Blue: `#2563EB`
- Sky: `#DCEEFF`
- Mist: `#F4F8FC`
- Paper: `#FFFFFF`
- Muted text: `#5E6B7A`
- Border: `#D8E2EC`
- Success accent: `#147A5A`

배경은 흰색과 아주 옅은 블루를 교차한다. 캐릭터의 짙은 블루가 가장 강한 브랜드 색으로 보이게 하고 CTA만 선명한 Action Blue를 사용한다.

### 5.3 타이포그래피

- 한국어 본문과 제목: `Pretendard Variable`, fallback `SUIT`, `Noto Sans KR`, sans-serif
- 영문 마이크로 라벨: 같은 폰트를 사용하며 자간만 조절한다.
- 히어로 제목은 데스크톱 64px 내외, 모바일 40px 내외로 설정한다.
- 본문 최대 폭을 제한해 한 줄이 지나치게 길어지지 않게 한다.

### 5.4 레이아웃과 표면

- 콘텐츠 최대 폭: 1200px
- 데스크톱 히어로: 텍스트 52%, 이미지 48%의 2열
- 주요 섹션 간격: 112~144px, 모바일 72~96px
- 모서리 반경: 카드 20~28px, 버튼 999px 또는 12px 중 맥락에 맞게 사용
- 그림자: 색이 강한 글로우 대신 낮은 불투명도의 블루-그레이 그림자
- 장식: 얇은 경로선, 점, 작은 도구 라벨. 콘텐츠보다 강하게 보이지 않게 한다.

## 6. 모션과 상호작용

- 내비게이션 앵커는 해당 섹션으로 부드럽게 이동한다.
- 섹션 진입 시 12~20px 이동과 페이드의 짧은 등장 모션을 사용한다.
- 히어로의 도구 라벨은 느리고 작은 부유 모션을 서로 다른 속도로 사용한다.
- 제품 미리보기는 hover 시 최대 4px 이동하고 그림자만 살짝 강화한다.
- `prefers-reduced-motion: reduce`에서는 모든 비필수 모션과 smooth scroll을 비활성화한다.
- 스크롤을 막거나 읽기 순서를 바꾸는 연출은 사용하지 않는다.

## 7. 반응형과 접근성

- 기준 폭: 모바일 우선, 768px 이상 태블릿, 1024px 이상 데스크톱
- 320px 너비에서도 가로 스크롤이 없어야 한다.
- 모든 본문 텍스트와 인터랙션은 WCAG AA 수준의 명도 대비를 만족한다.
- 키보드 포커스는 2px 이상의 명확한 링으로 표시한다.
- 캐릭터 이미지는 장면을 설명하는 대체 텍스트를 제공한다.
- 장식용 선과 점은 스크린리더에서 제외한다.
- CTA는 최소 44px 높이의 터치 영역을 확보한다.
- 비교표는 모바일에서 의미 순서를 유지하는 카드 목록으로 전환한다.

## 8. 구현 구조

랜딩사이트 폴더가 비어 있고 기존 `mobile`, `web` 프로젝트가 Vite와 React를 사용하므로, 동일한 계열의 독립적인 Vite + React 앱으로 구성한다.

- `src/content/landingContent.js`: 페이지 카피와 비교 데이터의 단일 출처
- `src/components/`: 내비게이션, 히어로, 비교, 여정, 기능 미리보기, CTA, 푸터
- `src/components/previews/`: 실제 서비스 흐름을 보여주는 정적 모바일 미리보기
- `src/styles/`: 토큰, 기본 스타일, 컴포넌트 스타일, 반응형 스타일
- `src/assets/`: 생성된 캐릭터 장면과 필요한 정적 자산
- `src/test/`: 렌더링, CTA 링크, 접근성 속성, 반응형 클래스 계약 테스트

페이지는 외부 API와 런타임 데이터에 의존하지 않는다. 모든 콘텐츠는 로컬 데이터로 렌더링해 네트워크 오류로 핵심 설명이 사라지는 상황을 만들지 않는다.

## 9. 오류와 대체 동작

- 생성 이미지가 로드되지 않으면 캐릭터 장면의 대체 텍스트와 CSS 도구 라벨이 의미를 유지한다.
- 웹폰트가 로드되지 않으면 시스템 한글 sans-serif로 자연스럽게 폴백한다.
- JavaScript가 늦게 실행돼도 정적 HTML 콘텐츠와 CTA는 먼저 보인다.
- `/explore`가 별도 서비스로 배포되는 경우 CTA URL은 한 곳의 콘텐츠 설정만 수정하면 되게 한다.

## 10. 검증 기준

- 단위/통합 테스트
  - 핵심 헤드라인과 두 기능 블록이 렌더링된다.
  - 모든 `모집 중인 동아리 보기` CTA가 `/explore`로 연결된다.
  - 비교 데이터의 네 단계가 정확한 기존 도구와 HSU Club 방식으로 표시된다.
  - 히어로 이미지에 설명형 alt가 존재한다.
- 정적 검증
  - ESLint 통과
  - Vite production build 통과
- 시각 검증
  - 1440px, 1024px, 768px, 390px, 320px 폭에서 캡처 확인
  - 가로 스크롤, 텍스트 잘림, 이미지 겹침 없음
  - 키보드 탭 순서와 포커스 표시 확인
  - reduced-motion 환경에서 불필요한 모션이 제거됨

## 11. 범위 제외

- 실제 회원가입과 로그인
- 동아리 검색 결과 및 상세 페이지 구현
- 운영진 대상 랜딩 메시지
- CMS 또는 서버 연동
- 사용자 후기와 성과 통계
- 다국어 지원
- 실제 약관 및 개인정보처리방침 본문 작성

- 서울과학기술대학교 공식 안내는 박람회, 소개집, SNS, 포스터, 에브리타임 등 여러 홍보 수단에서 모집 내용을 확인하도록 안내한다: https://www.seoultech.ac.kr/life/student/organ/club
- Google Sheets는 범용 공동 편집 문서이며 콘텐츠 보호와 공유 권한을 별도로 설정하는 구조다: https://support.google.com/docs/answer/9331169?hl=ko

이 자료는 “기존 도구가 나쁘다”는 주장이 아니라 “지원 여정이 여러 위치로 분산되어 있다”는 문제 정의의 근거로만 사용한다.
